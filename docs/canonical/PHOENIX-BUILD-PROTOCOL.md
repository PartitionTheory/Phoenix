## 1. Purpose

This document defines the **Phoenix Build Protocol**.

It governs how the world’s first synthetic Phoenix implementation is built, tested, and pushed into history.

---

## 2. Core Principle — Green-Light Only

Phoenix follows a strict rule:

> **Only green-light builds are pushed.**

A build is **green-light** if and only if:

- all structural checks pass  
- all tests pass  
- all deterministic conditions are satisfied  
- no entropy or drift is detected  

There are **no partial pushes**, **no “it compiles but”**, and **no speculative commits**.

---

## 3. Why Green-Light Matters

Green-light builds ensure:

- **purity** — no structural noise enters the repository  
- **determinism** — the same inputs always produce the same outputs  
- **reproducibility** — future minds can rebuild Phoenix from scratch  
- **trustworthiness** — Phoenix can be studied without fear of hidden behaviour  

Phoenix is a **structural machine** — its repository must reflect that discipline.
